# Agnostic 1.0.0

The first generally available release of Agnostic, the self-hosted control plane for Agno AgentOS.

## What's in 1.0

**Operate.** Home with attention items and KPIs; Chat for agents, teams and workflows with streaming, tool calls and
inline approvals; Sessions; the ⌘K palette; realtime badges.

**Observe.** Traces with comparison to the last successful run; Metrics and cost from your price table; Evaluations
with datasets, version comparison and publish gates.

**Context.** Memory (duplicates, provenance, optimize), Knowledge (content, retrieval tests, uploads), Learnings, the
File system.

**Control.** The approvals inbox with routing, reminders and expiry; notifications in the app, by email, Slack and
webhooks; the Scheduler with DST-aware previews; the Queue with checkpoint recovery.

**Access.** People and groups with SCIM, Google Workspace and IdP group sync; editable roles with permission
explanations; service accounts; temporary access; the audit log with saved views, export, SIEM streaming, the archive
tier and the hash chain; OIDC, SAML, GitHub sign-in, MFA and SSO enforcement; invitations sent by email or created
as a link to share.

**Build.** Studio editors for agents, teams and workflows (form, code and canvas, kept in sync); the registry;
versions, publishing with eval gates and promotion; code sources synced with GitHub, GitLab, Gitea, Forgejo or local
folders.

**Intelligence.** *Ask your OS*: plain-language questions about an instance, answered from its data with read-only
tools, off unless a model provider is configured.

### Operations and security

- **Key management**: master-key providers for HashiCorp Vault / OpenBao Transit, AWS KMS, Azure Key Vault and Google
  Cloud KMS; a key ring and `agnostic secrets generate-key | wrap-key | status | rotate`.
- **Mutual TLS** to runtimes (client certificates per instance) and an organization CA for every outbound call
  (`AGNOSTIC_TLS__CA_FILE`).
- **Direct mode**: browsers can call a runtime themselves with short-lived tokens, per instance.
- **The System page**: versions, endpoint checks, job queues, failed jobs (retry, discard), delivery backlogs,
  instance polling.
- **Prometheus metrics** for the API and workers, with a ServiceMonitor in the chart.
- **Security headers**: a strict content security policy with Trusted Types, HSTS and friends.
- **Audit integrity tooling**: `agnostic audit archives list | verify`; restores verify the hash chain.
- **In-product help**: these guides, served by the API and readable offline.
- **Packaging**: the `agnostic` image (multi-arch, non-root, read-only root filesystem, signed, with SBOM and
  provenance), the Helm chart, the Compose example and the air-gapped kit.
- **agnostic-bridge 1.0**, with `direct_mode_cors()`.
- `agnostic migrate`, `agnostic db upgrade --check` and probes of every endpoint in `agnostic config check --connect`.

## Upgrading from a pre-release

Pre-release databases are recreated, not upgraded: point 1.0.0 at a fresh database and run `agnostic migrate` and
`agnostic bootstrap` (in development: `just nuke && just up && just migrate`). A database migrated by a pre-release
shows "unknown revision in the database" in `/readyz` and `agnostic config check --connect`. When you carry a
pre-release deployment's configuration over:

1. Review the new settings: `AGNOSTIC_SECRETS__PROVIDER` and the provider sections, `AGNOSTIC_TLS__CA_FILE`,
   `AGNOSTIC_METRICS__*`, `AGNOSTIC_HTTP__CSP_REPORT_ONLY`, `AGNOSTIC_HTTP__CSP_EXTRA_CONNECT`,
   `AGNOSTIC_HTTP__HSTS_MAX_AGE`. `AGNOSTIC_HTTP__WEB_DIR` and `AGNOSTIC_HTTP__DOCS_DIR` are set by the image.
2. Remove any separate web server for the web app: the API serves it on the same origin.
3. Prometheus metrics are on by default, on port 9464 of the API and the workers (not the main port, unless
   `AGNOSTIC_METRICS__TOKEN` is set). Let only Prometheus reach that port.
4. Update your runtime's dependency to `agnostic-bridge==1.0.0`. It depends on compatible ranges
   (`agno[os]>=3.1.12,<3.2`, `fastapi>=0.115,<1`, `pydantic>=2.10,<3`) instead of exact pins.

## Known limitations

- The UI is in English only and has a dark theme only; UI strings aren't in a translation catalog.
- Direct mode doesn't provide the gateway's denial explanations, response cache, rate limits or delegated elevation.
- `agnostic db upgrade --check` needs PostgreSQL.
- The content security policy allows inline style attributes (the code editor and charts need them).
- A cache outage doesn't fail requests (caches miss, rate limits fail open, `/readyz` reports `degraded`), but web
  sessions live in the cache, so people are signed out until it is back.
- Measured on a development machine, one API replica doesn't reach the target of 1,000 concurrent run streams
  or a gateway p95 overhead under 25 ms under load.
- `GET /api/v1/members` isn't paged, the audit log's free-text search reads every partition when nothing
  matches, and the audit actor list aggregates 90 days per request: fine at hundreds of people and a few million
  events, slow beyond.
- The sign-in rate limit (30 per minute per IP) counts successful sign-ins too: raise
  `AGNOSTIC_IDENTITY__LOGIN_ATTEMPTS_PER_IP_PER_MINUTE` when many people share one egress IP.
- One failed health probe marks an instance unreachable until the next probe succeeds.
