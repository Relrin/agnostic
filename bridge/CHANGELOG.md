# Changelog

## Unreleased

- Coding agents: `agnostic_bridge.coding.PiAgent` and `OpenCodeAgent` run Pi and OpenCode in a sandbox per session
  (`DockerProvider`, or `E2BProvider` with the `e2b` extra) on an Agno model. The model and the agent's tools are
  served to the sandbox by the runtime (`/agnostic/v1/coding/llm/v1`, `/agnostic/v1/coding/mcp`) with a token per
  turn, ahead of the AgentOS auth layer. Published Studio agents with `metadata.agnostic.coding_agent` are served as
  coding agents. New routes: `GET /coding-agents`, `POST /coding-agents/refresh`; `install(coding=CodingConfig(...))`;
  `/capabilities` reports `coding_agents`. `capture_artifacts` collects from a coding agent's live sandbox.

- Artefacts: `agnostic_bridge.artifacts` collects the files agents write into run media, from a folder
  (`DirectorySource`), an E2B sandbox (`E2BSource`) or an Agno sandbox checkpoint (`CheckpointSource`). Use the
  `collect_artifacts` post-hook, the `ArtifactTools` publish tool, or `capture_artifacts` on `ClaudeAgent`/`CodexAgent`.
  New routes: `GET /artifacts`, `GET /artifacts/recent`, `POST /artifacts/sync`; `/capabilities` reports
  `media_storage`.

- Tool catalog: with `AGNOSTIC_CONTROL_PLANE_URL`, `AGNOSTIC_INSTANCE_ID` and `AGNOSTIC_TOOL_CATALOG_TOKEN` set (or
  `install(agent_os, tool_catalog=ToolCatalogConfig(...))`), the bridge pulls its instance's approved MCP servers and
  Agno toolkits from the control plane and keeps them in the AgentOS registry. New routes: `GET /tool-catalog/status`,
  `POST /tool-catalog/sync`, `POST /tool-catalog/probe`, `GET /toolkits`; `/capabilities` reports `tool_catalog`.
- Catalog entries read only the environment variables listed in `AGNOSTIC_TOOL_CATALOG_ENV` (never `AGNOSTIC_*`);
  stdio servers need `AGNOSTIC_TOOL_CATALOG_ALLOW_LOCAL=true` whatever the entry says, and get a minimal environment.
- `toolkits.json`: the Agno toolkits a catalog entry may name, generated by `scripts/dump_toolkits.py`.

## 0.1.0

First release, for Agno AgentOS 3.1.x.

- Routes under `/agnostic/v1`: capabilities, component validate/normalize, evals, file provenance, workers,
  events, code-component and registry introspection, CEL evaluation.
- `direct_mode_cors()`: CORS for the control plane's origin when browsers call AgentOS directly.
- Dependencies are compatible ranges (`agno[os]>=3.1.12,<3.2`, FastAPI, pydantic) instead of exact pins, so the
  bridge installs into existing AgentOS apps.
